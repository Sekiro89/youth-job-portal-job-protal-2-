## Decisions (from the client)
1. **Pricing:** employers **$14.99**/posting/month, third-party consultants **$9.99**/posting/month, **plus 5% GST** (employer total $15.74, consultant total $10.49). Recurring until cancelled. Receipts downloadable from Billing. `lib/constants.js`: `PRICING`, `priceCentsFor(role)`; env `EMPLOYER_PRICE_CENTS` / `CONSULTANT_PRICE_CENTS` override; settings keys `employer_price_cents` / `consultant_price_cents`. The price is decided by the PAYER's role (`users.role`), snapshotted onto `subscriptions.price_cents/tax_cents/total_cents` at checkout.
2. **Education & experience:** dropdown + optional free text. `C.EDUCATION_LEVELS` (keys incl. `other`) → `jobs.education` stores the KEY; `jobs.education_other` free text (required when `other`). `C.EXPERIENCE_LEVELS` gained `other` → `jobs.experience_other`. Display: `h.educationName(key)` / `h.experienceName(key)`, and show the `_other` text when key = other. Existing rows may hold legacy free-text education — display raw if the key is unknown.
3. **Industry:** dropdown only (`C.CATEGORIES`), no manual industry. NOC code stays a typeable text field (until the client's CRM link exists).
4. **Salary period:** `C.SALARY_PERIODS` = hour | day | week | biweekly | month | year. `h.formatSalary(job)` handles all. For search/sort annualise with `C.SALARY_PERIOD_TO_YEAR[period]`.
5. **Work location — full address, multiple per posting.** New table `job_locations(job_id, street_address, unit, city, province, postal_code, sort_order)`. Native postings: at least one location; every location needs street_address, city, province, postal_code (validate with `C.POSTAL_CODE_RE`, store via `h.formatPostal`). `jobs.city/province` = first location (keep in sync on save). Public display: "Work location(s)" block listing each full address on its own line (`h.fullAddress(l)`), Job Bank style. Imported Job Bank rows have only city/province (street NULL) — display those as "City, Province".
6. **Operating / trade name:** `employer_profiles.operating_name` (+ `street_address`, `postal_code` on the profile as the default first work location). Seekers see the operating name first; legal name secondary: `h.displayCompany(profile)` and `h.legalNameNote(profile)`. Signup + profile forms collect it (optional; hint "e.g. Flying Pig — the name customers know you by").
7. **Job Bank imports = reference only.** Badge/attribution must say "Reference posting from Job Bank (Government of Canada) — not posted on Canada Careers". They never carry subscriptions.
8. **Apply flow:** optional **cover sheet upload** (pdf/doc/docx ≤5 MB → `applications.cover_letter_path/cover_letter_name`, stored under `UPLOAD_DIR/covers/`), resume auto-attached from the profile if present, otherwise uploaded on the spot (and saved to the profile). Guests are sent to sign up / log in and returned to the apply page. Employers/consultants download both files from the applicants page.
9. **Printable seeker view:** job detail page gets a "Print / save as PDF" button and a print stylesheet: operating name, legal name, full addresses, salary with period, everything on one clean sheet.
10. SEO/GEO/AEO is already built; nothing to do. Stripe keys are pending from the client (sandbox stays). "Connect Job Bank login to pull/post" is out of scope (no API).
