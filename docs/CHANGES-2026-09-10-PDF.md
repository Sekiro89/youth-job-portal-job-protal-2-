## Decisions (PDF + call)
1. Company **Industry** = dropdown of `C.INDUSTRIES` (no free text) on employer profile forms + employer signup. Legacy free text rows display raw.
2. **Education / Experience** dropdowns = the new Job Bank lists + "Other (specify)".
3. **Work hours**: "Number of hours worked" (`hours_amount`, numeric) + frequency (`hours_period`: week | biweekly | month | year). Optional on the form; shown as "35 hours per week".
4. **Locations live on the employer profile** (`employer_locations`, add/edit/archive, one default). Posting a job = tick one or more of the profile's locations (+ "Add a new location" inline, which also saves to the profile). Selected locations are snapshotted into `job_locations` (with `employer_location_id`). At least one required. Every selected location is printed clearly on the public posting.
5. **Operating names**: profile holds a LIST (`operating_names[]`, `operating_name` = default). Job form has "Operating name for this posting" select (profile list + "add new" which appends to the profile). Display order: `job.operating_name || profile.operating_name || company_name` via `h.displayCompany({operating_name, company_name})`, legal name secondary.
6. **Application email** on the job form defaults to the SELECTED employer profile's `contact_email` (falls back to the owner user's email only if the profile has none) — never the consultant's own email by default; label "Application email (the employer's inbox)".
7. **Client admin panel** (`/admin/integrations`, passcode-gated): Stripe keys (+ "Test connection", "Create prices & webhook"), Email provider (SMTP URL or Resend key, sender name/email, "Send test email"), Support routing (recipients for Contact Us — Veda's address goes HERE as a recipient, nothing is ever sent FROM it), Pricing + GST number, Branding, Google Maps key, Job Bank sync on/off, Admin users (create/disable additional admin logins with their own passwords — "everybody has their own backend"). Everything reads through `lib/settings` at runtime; no restart needed.
8. **Maps**: provider abstraction — Google (Maps JS + Places Autocomplete + Geocoding) when `google_maps_api_key` is set, otherwise Leaflet + OpenStreetMap tiles + Nominatim geocoding (1 req/s, cached in `geocode_cache`). Every location is geocoded server-side on save (and by a cron for backlog). Job page: map with a pin per location. Search: map view with markers, "Near me" (browser geolocation) + radius filter, and a `lat/lng/radius_km` API for the results. Address autocomplete on the location forms when Google is available.
